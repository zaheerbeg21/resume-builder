# T-002: Local Dev Environment, Supabase CLI/Docker Setup, .env.example, & CI Pipeline

## 1. Goal
Establish a reproducible local development environment using Docker and the Supabase CLI, document environment variables and secret management via `.env.example`, and implement automated continuous integration with GitHub Actions running tests, linting, and TypeScript compilation.

## 2. Owner Role & Test Author
- **Owner Role:** DevOps/SRE
- **Test Author:** DevOps/SRE

## 3. Allowed Files
- `supabase/config.toml` (local Supabase configuration for Postgres, Auth, Storage)
- `.env.example` (template with documented variable definitions and dummy values)
- `.github/workflows/ci.yml` (GitHub Actions CI pipeline definition)
- `vitest.config.mts` (Vitest test configuration and path resolution)
- `tests/env.test.ts` (test asserting required environment variables are parsed correctly)

## 4. Human-Only Prerequisites
- Human review and approval of all variable names and secret handling patterns in `.env.example`.
- Human setup of repository secrets in GitHub for CI environment variables.

## 5. New Dependencies for Human Approval
- `supabase` CLI (run via `npx supabase` or installed locally; no runtime npm dependency added to `package.json`).

## 6. Dependencies
- None.

## 7. Acceptance Criteria
1. **Local Supabase Environment:** `supabase/config.toml` defines local services (Postgres on port 54322, Studio on port 54323, Inbucket for mock emails on port 54324, Auth, and Storage). Instructions provided for `npx supabase start` and `npx supabase stop`.
2. **Environment Variable Template:** `.env.example` lists every required application variable:
   - `NEXT_PUBLIC_SUPABASE_URL`
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   - `SUPABASE_SERVICE_ROLE_KEY`
   - `GEMINI_API_KEY`
   - `GEMINI_MODEL_FAST`
   - `GEMINI_MODEL_QUALITY`
   - `STRIPE_SECRET_KEY`
   - `STRIPE_WEBHOOK_SECRET`
   - `NEXT_PUBLIC_APP_URL`
   Each variable includes clear comments detailing its purpose, whether it is client-safe or server-only, and dummy fallback values.
3. **CI Pipeline (`.github/workflows/ci.yml`):**
   - Triggers on all pushes to `master` and all pull requests targeting `master`.
   - Runs on `ubuntu-latest` with Node.js 20.x.
   - Executes:
     1. `npm ci`
     2. `npm run lint`
     3. `npx tsc --noEmit`
     4. `npm test`
   - Fails the build if any of the above commands exit with a non-zero status.
4. **Environment Parser Test:** `tests/env.test.ts` validates that a Zod schema parses valid environment configurations and fails with descriptive errors when mandatory keys are missing.
