# T-008: Resume CRUD API & Storage Layer

## 1. Goal
Implement secure, type-safe Next.js Route Handlers for creating, reading, updating, and deleting resumes, strictly enforcing `ResumeSchema` validation and the 5-resume per user limit at the API boundary and database level.

## 2. Owner Role & Test Author
- **Owner Role:** Backend Engineer
- **Test Author:** Backend Engineer

## 3. Allowed Files
- `app/api/resumes/route.ts` (Collection route handler: list, create)
- `app/api/resumes/[id]/route.ts` (Item route handler: get, update, delete)
- `lib/db/resumes.ts` (Database access helper functions)
- `tests/api/resumes.test.ts` (Integration tests for API endpoints)

## 7. Acceptance Criteria
1. **List Resumes (`GET /api/resumes`):**
   - Requires authenticated session; returns 401 if unauthenticated.
   - Returns JSON array of resumes for the authenticated user, ordered by `updated_at desc`.
2. **Create Resume (`POST /api/resumes`):**
   - Requires authenticated session.
   - Pre-flight check: counts user's current resumes; if $\ge 5$, returns HTTP 403 with `{ error: "Resume limit reached. Maximum 5 resumes allowed." }`.
   - Validates request body using `ResumeSchema.safeParse()`; returns HTTP 400 with validation details if invalid.
   - Inserts record into `resumes` table. If database trigger raises quota exception, catches and maps to HTTP 403.
   - Returns HTTP 201 with created resume object.
3. **Get Resume by ID (`GET /api/resumes/[id]`):**
   - Queries resume where `id = params.id` and `user_id = auth.uid()`.
   - Returns 404 if not found (avoiding leaking existence of other tenants' resumes).
   - Returns HTTP 200 with resume content.
4. **Update Resume (`PUT /api/resumes/[id]`):**
   - Validates incoming body against `ResumeSchema`.
   - Updates `content`, `title`, `template`, and `updated_at`.
   - Returns HTTP 200 with updated record; returns 404 if resume does not exist or belongs to another user.
5. **Delete Resume (`DELETE /api/resumes/[id]`):**
   - Deletes resume where `id = params.id` and `user_id = auth.uid()`.
   - Returns HTTP 204 No Content.
6. **Zero Content Logging:**
   - Under no circumstances is resume content (personal info, bullets, employment) logged to console, Sentry, or logs.
   - Logs only operation metadata: `{ op: "resume:create", userId: "...", resumeId: "...", timestamp: "..." }`.
7. **Integration Tests (`tests/api/resumes.test.ts`):**
   - Asserts full CRUD lifecycle for an authenticated user.
   - Asserts attempting to create a 6th resume returns HTTP 403 with quota error.
   - Asserts updating another user's resume returns HTTP 404.
