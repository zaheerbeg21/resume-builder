# T-014: Cross-Engine Page-Count Parity Verification Suite

## 1. Goal
Implement an automated, browser-integrated verification test harness across 20 diverse fixture resumes to guarantee 100% page-count and line-break parity between the in-browser live preview canvas and the server-rendered exported PDF.

## 2. Owner Role & Test Author
- **Owner Role:** Document Engineer
- **Test Author:** QA Engineer (QA authors the 20 test fixtures and the parity verification harness)

## 3. Allowed Files
- `tests/fixtures/resumes/fixture-01-minimal.json` through `fixture-20-*.json` (20 diverse test resumes)
- `tests/pdf-parity.test.ts` (Node-side export page count and extraction harness)
- `tests/browser/preview-parity.test.ts` (Browser-based preview canvas and page inspection test)
- `tests/helpers/pdf-parity-checker.ts` (Shared parity evaluation utilities)

## 4. Human-Only Prerequisites
- Human review and approval for using Playwright or Vitest Browser Mode for automated browser rendering tests.

## 5. New Dependencies for Human Approval
- Playwright or Vitest Browser Mode (for executing real headless browser tests verifying `<PDFViewer>` canvas page counts).

## 6. Dependencies
- T-011 (Standard and Classic templates)
- T-012 (ATS Format Lint engine)
- T-013 (Live PDF Preview component)

## 7. Acceptance Criteria
1. **20 Comprehensive Golden Fixtures:**
   - Fixture suite covers edge cases:
     - 1-page compact junior resume.
     - 2-page senior engineering manager resume with 5 roles.
     - Resume with no education section.
     - Resume with career gap years.
     - Resume with heavy skills categorization (6 groups, 40+ items).
     - Resume with maximum bullets (8 per job, 300 characters each).
     - Accented names: "Renée Noël Müller", "Łukasz Żółć", and non-ASCII character sets.
     - Resumes right on the verge of 1-page vs 2-page thresholds.
2. **Browser-Based Preview Verification (Not Node-Only):**
   - The parity verification MUST NOT rely solely on Node server calculations.
   - `tests/browser/preview-parity.test.ts` mounts `<ResumePreview>` in an automated headless Chromium browser environment.
   - The test evaluates the actual DOM canvas rendering of React-PDF (`page` container elements or canvas layer), extracting the computed preview page count and rendered dimensions.
3. **Export Engine Verification:**
   - Simultaneously renders the identical fixture with `@react-pdf/renderer`'s `renderToBuffer` in Node.
   - Uses `pdf-parse` v2 to extract the physical PDF page count (`parser.getPageCount()` / page markers).
4. **Strict Parity Assertions (40 Evaluations):**
   - Evaluates all 20 fixtures across both Standard and Classic templates ($20 \times 2 = 40$ runs).
   - Assert: **Browser Preview Page Count == Exported PDF Page Count** for all 40 runs ($100\%$ parity pass rate).
   - Assert: Headings and company titles do not split into isolated orphan headers at the bottom of pages.
   - Assert: Extracted text from all 20 exported PDFs contains 0 unicode replacement characters (`\uFFFD`) and 100% of headings and dates in reading order.
5. **Lint Rule Validation:**
   - Runs `lintResume()` on all 20 exports, verifying that all valid fixtures pass with zero hard lint errors.
