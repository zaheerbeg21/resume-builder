# T-016: AI Evaluation Harness & Per-Task Approval Gate

## 1. Goal
Implement an automated, reproducible evaluation harness and per-task quality approval gate. Benchmark candidate LLM models (primary Gemini and secondary OpenAI-compatible endpoints) across three discrete tasks (resume parsing, JD keyword extraction, and fact-constrained bullet optimization). Provide objective metrics—keyword recall/precision against ground-truth labels, zero-digit fabrication rate on adversarial inputs, and schema conformance—to gate model activation before any provider/model is enabled in production.

## 2. Interface Contract
All evaluation logic and scorecard generators reside under `lib/ai/eval/` and scripts:

```ts
import { z } from 'zod';
import type { LlmProvider } from '@/lib/ai/types';

export type EvalTask = 'parse_resume' | 'analyze_jd' | 'optimize_bullet';

export interface KeywordGroundTruth {
  term: string;
  importance: 'required' | 'preferred';
  category: string;
}

export interface JdFixture {
  id: string;
  title: string;
  rawText: string;
  groundTruthKeywords: KeywordGroundTruth[];
}

export interface AdversarialBulletFixture {
  id: string;
  originalText: string;
  allowedDigits: string[];       // Digits legitimately present in input
  forbiddenNumbers: string[];    // Plausible hallucinations to detect
}

export interface TaskEvalScorecard {
  task: EvalTask;
  provider: string;
  model: string;
  schemaPassRate: number;        // Target: 1.0 (100%)
  precision?: number;            // For analyze_jd (target >= 0.80)
  recall?: number;               // For analyze_jd (target >= 0.85)
  inventedDigitCount?: number;   // For optimize_bullet (strictly 0)
  p95LatencyMs: number;
  estCostPerCallUsd: number;
  approvedForProduction: boolean;
  rejectionReasons: string[];
}
```

- `scripts/run-eval.ts`: CLI entrypoint executing evaluation suites against configured providers/models.
- `lib/ai/eval/harness.ts`: exports `runTaskEvaluation(provider: LlmProvider, task: EvalTask): Promise<TaskEvalScorecard>`.
- `lib/ai/eval/metrics.ts`: pure functions computing precision, recall, digit-guard violations, and latency statistics.

## 6. Stop Conditions
- If any candidate model invents numbers or digits on the 30 adversarial bullets, it is **strictly disqualified** from the bullet improver task.
- Do NOT hardcode specific model recommendations in code or docs. All candidate models are marked **TBD pending evaluation**.

## 7. Golden Sets Specification (Authored by QA Engineer)
1. **20 Resume Fixtures (`tests/fixtures/eval/resumes/`):**
   - High diversity: standard tech resumes, career switchers, non-traditional education, multi-page senior profiles, short single-role resumes, accented names (`Renée Noël Müller`, `Łukasz Żółć`), and complex date formats.
2. **15 Job Description Fixtures (`tests/fixtures/eval/jds/`):**
   - 15 distinct real-world job postings across software engineering, product management, DevOps, data science, and technical sales.
   - Hand-labeled ground truth keywords annotated with exact term, accepted aliases, importance (`required` vs. `preferred`), and category (`hard_skill`, `tool`, `method`, `qualification`, `domain`).
3. **30 Adversarial Bullet Fixtures (`tests/fixtures/eval/bullets/adversarial.json`):**
   - Vague bullets tempting metrics fabrication (e.g., "Led migration of legacy systems to cloud, improving uptime and team efficiency").
   - Bullets with existing specific numbers (e.g., "Reduced latency from 450ms to 85ms on 3 microservices") to ensure original numbers are preserved while new ones are not added.
   - Bullets with percentages, dollar amounts, and team headcounts.

## 8. Per-Task Approval Gate Thresholds

A candidate model cannot be enabled in production for a given task unless it satisfies all thresholds for that task:

### Task 1: Resume Parsing (`/api/ai/parse-resume`)
- **Schema Conformance:** 100% of 20 resumes successfully validate against `ResumeSchema` without crashing.
- **Verbatim Entity Retention:** 0 hallucinated employers or degrees; unstated dates returned as `null` (not guessed).
- **Confidence Calibration:** Confidently flags low-confidence or unparseable paths into `low_confidence_paths`.

### Task 2: JD Keyword Extraction (`/api/jd/analyze`)
- **Required Keyword Recall:** >= 85% recall on required keywords across all 15 hand-labeled JDs.
- **Keyword Precision:** >= 80% precision (excludes conversational filler such as "passionate team player").
- **Schema Conformance:** 100% conform to `JdAnalysisSchema` with maximum 40 keywords.

### Task 3: Fact-Constrained Bullet Improver (`/api/ai/bullet-optimize`)
- **Zero Invented Digits:** **Strictly 0 invented digits** across all 30 adversarial test bullets. Any fabricated number or metric causes immediate gate rejection.
- **Placeholder Generation:** Correctly outputs bracketed placeholders (e.g., `[X%]`) and explanatory questions when metrics are absent.
- **Variant Count & Length:** Exactly 3 variants per bullet, each constrained to 12–32 words.

### Operational & Economic Envelope
- **Latency:** p95 latency under 4,000ms.
- **Cost:** Estimated token cost fits within the $3.80 per active user budget envelope.

## 9. Acceptance Criteria
1. **Fixture Completeness:**
   - All 20 resumes, 15 ground-truth labeled JDs, and 30 adversarial bullets exist and validate against schema.
2. **Deterministic Metric Computation:**
   - Precision, recall, and digit-guard violation checks in `lib/ai/eval/metrics.ts` are pure functions covered by unit tests.
3. **Evaluation CLI:**
   - `scripts/run-eval.ts` can be executed with `--provider=<name>` and `--task=<task>` to run automated evaluations and output formatted markdown/JSON scorecards.
4. **CI Integration (Offline):**
   - `npm test` runs `tests/eval-harness.test.ts` using `FakeLlmProvider` with zero network overhead.
5. **No Model Recommendations Hardcoded:**
   - Evaluator accepts model identifiers dynamically; all default configurations remain marked TBD pending evaluation runs.
6. **Digit-fabrication Rate:**
   - Digit-fabrication Rate measured on raw first-attempt model output, before retries and before the production digit guard. The production guard is verified separately and must catch 100% of injected invalid digits.
