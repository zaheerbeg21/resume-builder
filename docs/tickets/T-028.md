# T-028: COPPA Compliance: Age Verification Screen & Under-Age Account Block

## 1. Goal
Ensure compliance with age verification requirements (including the U.S. Children's Online Privacy Protection Act, 15 U.S.C. §§ 6501–6506, and relevant international standards) by implementing an age gate that prevents underage users from registering an account or submitting personal identifiable information (PII). The minimum age must be defined as a single configurable constant (`lib/auth/config.ts`), not hardcoded, with explicit documentation that the age threshold must be confirmed with legal counsel because digital consent ages vary internationally (e.g., between 13 and 16 years across EU member states under GDPR Art. 8). The enforcement must operate server-side (not client-only), immediately terminate registration for underage users, and avoid persisting underage data. A cookie-based block is used to prevent immediate back-button/refresh bypass; it is explicitly recognized and accepted that clearing browser cookies can circumvent this block (an accepted engineering limitation).

## 2. Interface Contract
- **Centralized Age Configuration:**
  - File: `lib/auth/config.ts`
  - Export: `export const MINIMUM_REGISTRATION_AGE = 13;` (Single source of truth).
  - Code comment: Must state that the threshold must be confirmed with legal counsel, noting that while COPPA establishes 13 in the United States, EU GDPR Art. 8 allows individual member states to set the age of digital consent between 13 and 16 (e.g., 13 in the UK/Ireland, 14 in Austria/Italy, 15 in France, 16 in Germany/Netherlands).
- **Age Gate Options for Human Selection (see Section 7):**
  - **Option A (Neutral Date-of-Birth Entry):**
    - Neutral prompt requesting Month, Day, Year of birth.
    - Zero indication of the required age threshold in labels, placeholders, or copy (prevents coaching minors to lie).
    - Validation computes user age against `MINIMUM_REGISTRATION_AGE`: `age = (today - birthDate) >= MINIMUM_REGISTRATION_AGE`.
  - **Option B (Age Affirmation Checkbox):**
    - Explicit checkbox: *"I confirm that I meet the minimum registration age requirement."*
    - Simpler UI, but signals the threshold to minors.
- **Under-Age Block Enforcement Mechanism:**
  - If the user fails the age check (calculated age < `MINIMUM_REGISTRATION_AGE` or unchecked confirmation):
    - Client registration is immediately blocked.
    - An HTTP-only, secure, SameSite session cookie is issued: `coppa_blocked=true; Max-Age=86400; Path=/; SameSite=Strict; Secure`.
    - No user record or profile is inserted into Supabase (`auth.users`, `profiles`).
    - The entered email, password, and birthdate are wiped from memory and never written to database storage.
  - While `coppa_blocked=true` cookie is present, subsequent registration attempts are rejected with a neutral rejection screen: *"You are not eligible to register for an account at this time."*
  - **Accepted Limit:** Clearing browser cookies or using private/incognito browsing can bypass this cookie-based block. This is an explicitly accepted engineering limitation for the MVP (`shortcut: cookie-based block can be cleared by user, upgrade to IP-subnet or device fingerprinting only if abuse is demonstrated`).
- **Server-Side Enforcement:**
  - **API Route:** `POST /api/auth/age-gate`
    - Accepts DOB or affirmation, validates against `MINIMUM_REGISTRATION_AGE` server-side, and sets `coppa_verified` or `coppa_blocked` HTTP-only cookie.
  - **OAuth Callback Guard:** `app/(auth)/callback/route.ts`
    - Verifies age gate status before finalizing OAuth exchange for new accounts.

## 4. Session Order (Multi-Phase Workflow)
1. **Phase 0 — Stubs (Frontend/Backend Engineer):** Create stubs for `lib/auth/config.ts`, `components/auth/AgeGateScreen.tsx`, and `app/api/auth/age-gate/route.ts`.
2. **Phase 1 — Tests First (QA Engineer):** Write `tests/auth/age-gate.test.ts` verifying:
   - Dynamic calculation against `MINIMUM_REGISTRATION_AGE` correctly identifies underage vs qualifying ages across leap years and timezones.
   - Changing `MINIMUM_REGISTRATION_AGE` dynamically updates validation without code modifications elsewhere.
   - Submitting an underage DOB sets `coppa_blocked` cookie and terminates flow without calling `supabase.auth.signUp`.
   - Submitting a qualifying DOB allows registration to proceed.
   - OAuth callback enforces age gate check before session finalization.
   - Zero storage: verifies database client is never called with underage credentials.
   - Confirm tests fail on assertions (red state).
3. **Phase 2 — Implementation (Frontend/Backend Engineer):** Implement config, UI components, cookies, and route handlers until all tests pass (green state).
4. **Phase 3 — Independent Code Review (Code Reviewer):** Inspect diff to confirm single config value, server-side enforcement, zero storage, and documented bypass limit.

## 6. Stop Conditions
- If `MINIMUM_REGISTRATION_AGE` is hardcoded anywhere outside `lib/auth/config.ts`, **STOP and report immediately**.
- If the implementation stores the underage child's email, password, or DOB in PostgreSQL or localStorage, **STOP and report immediately**.

## 7. Human-Only Prerequisites
- **Human Decision Required — Confirm Minimum Age & Jurisdictional Scope:**
  The repository owner must confirm the numerical value of `MINIMUM_REGISTRATION_AGE` (default: 13) with qualified legal counsel. If the application targets users in the European Union or United Kingdom, counsel must advise whether country-specific thresholds (up to 16 years) or a unified threshold should be enforced.
- **Human Decision Required — Select Age Gate Design:** The owner must select between Option A and Option B:

| Metric | Option A: Neutral Date-of-Birth Entry | Option B: Age Affirmation Checkbox |
|---|---|---|
| **Compliance Rating** | **Commonly recommended; confirm with a lawyer** (Avoids signaling the qualifying threshold, discouraging minors from falsifying data) | **Higher regulatory risk** (Directly signals the age requirement, incentivizing underage users to check the box) |
| **Registration Friction** | Slightly higher (User must select or enter Month, Day, Year) | Very low (Single click on a checkbox) |
| **Data Collection** | Evaluates DOB in memory; discarded immediately if underage; never stored | Collects no birth date; records boolean consent only |
| **Bypass Limit** | Clearing browser cookies can bypass the block (accepted limit) | Clearing browser cookies can bypass the block (accepted limit) |

*The ticket implementation will default to Option A unless explicitly directed to use Option B by the owner.*

## 10. Acceptance Criteria
1. **Single Source of Truth Config:** `MINIMUM_REGISTRATION_AGE` is defined exclusively in `lib/auth/config.ts` and imported by all validators and routes.
2. **Server-Side Enforcement:** Age validation logic executes server-side, not merely in client UI state.
3. **Underage Rejection:** Submitting a date of birth below `MINIMUM_REGISTRATION_AGE` immediately blocks registration.
4. **Temporary Block Cookie with Documented Limit:** A secure, HTTP-only `coppa_blocked` cookie is issued. The code includes a comment explicitly recognizing that users can clear cookies as an accepted MVP limit.
5. **Zero Persistence of Child Data:** The server and client make zero calls to insert the blocked user's email, password, or birth date into `auth.users`, `profiles`, or any database table.
6. **OAuth Protection:** Users initiating Google OAuth must satisfy the age check before account creation is permitted.

## 11. Open Risk / Infrastructure Note
- EU digital consent laws (GDPR Art. 8) vary by country (13 to 16). If international expansion occurs, the single config value can be expanded to GeoIP-aware thresholds.
