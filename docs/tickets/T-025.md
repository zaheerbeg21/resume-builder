# T-025: Format-Agnostic `/api/ai/parse-resume` Route & Async Job Polling

## 1. Goal
Replace the existing brittle regex implementation in `app/api/ai/parse-resume/route.ts` with the production-ready format-agnostic parsing pipeline. Enforce that MVP import is strictly PDF-only (DOCX import is explicitly deferred). Implement asynchronous 202 job creation and a dedicated status polling endpoint backed by `parse_jobs` (T-020) to prevent serverless function timeouts under unconfirmed Vercel duration limits (*verify in current Vercel docs*). Ingest through the private storage pipeline (T-020), execute the Stage 1 parser adapter (T-024), enforce authentication, rate limits, and per-user request quotas, sanitize error responses, guarantee raw document deletion in a `finally` block, and record per-call telemetry into `usage_events` (Blueprint §5 and §10).

## 7. Acceptance Criteria
1. **Scope: PDF Only (DOCX Deferred):**
   - Strictly accepts `application/pdf` uploads. DOCX parsing is rejected with an explicit HTTP 400 (`error: "DOCX format is not supported for MVP; please upload a PDF"`).
2. **Asynchronous 202 Job Creation (`POST /api/ai/parse-resume`):**
   - Accepts `{ storagePath: string }` from authenticated user.
   - Validates user ownership of `storagePath` and asserts PDF magic bytes (`%PDF`).
   - Inserts row into `parse_jobs` with `status = 'pending'`.
   - Dispatches background processing and immediately returns HTTP 202 Accepted within $< 500\text{ms}$:
     ```json
     { "jobId": "uuid", "status": "pending", "pollUrl": "/api/ai/parse-resume/status/uuid" }
     ```
3. **Status Polling Endpoint (`GET /api/ai/parse-resume/status/[id]`):**
   - Requires session authentication; enforced by RLS on `parse_jobs`.
   - Returns `{ jobId, status: 'pending' | 'processing' | 'completed' | 'failed', result?, error? }`.
   - When completed, returns `ResumeImportDraft` payload.
4. **Guaranteed Storage Purge:**
   - Guarantees immediate deletion of raw uploaded document from Supabase Storage within a `finally` block upon task termination or failure.
5. **Scan & Short-Text Fallback:**
   - If extracted text stream is $< 200$ characters, marks job `failed` with `{ isScan: true, error: "Extracted text is too short..." }` without invoking LLM providers.
6. **Failure Handling:**
   - On terminal parsing failure (after 3 attempts exhausted), marks job `failed` with `{ parse_failed: true, is_scan: false, manual_fallback: true }`.
   - Never injects synthetic placeholders (zero `'candidate@example.com'`, zero `'Company'`).
   - Does not return internal error stacks or exception details to the client.
7. **Quota Accounting & Rate Limiting:**
   - Enforces user request quota strictly once per incoming user request (internal retries and failovers do not double-decrement quota).
   - Enforces per-user and per-IP rate limits via Upstash/Supabase.
8. **Telemetry Logging (`usage_events`):**
   - Writes a record to `usage_events` upon completion: `route = '/api/ai/parse-resume'`, `provider`, `model`, `failed_over_from`, `latency_ms`, `input_tokens`, `output_tokens`, and preliminary `est_cost_usd` *(starting placeholder)*.
