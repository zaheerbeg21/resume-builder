# T-027: Statutory Legal Page Scaffolding (Privacy Policy & Terms of Service with Placeholders)

## 1. Goal
Scaffold static, clean, responsive pages for `/privacy` (`app/(marketing)/privacy/page.tsx`) and `/terms` (`app/(marketing)/terms/page.tsx`), and prepare their footer integration in `components/marketing/Footer.tsx`. To ensure complete legal safety, the engineer must NOT invent legal text, warranty clauses, or corporate representations. All required corporate, contact, and jurisdictional terms must be represented exclusively by clearly marked `[OWNER: ...]` placeholders. A prominent disclaimer must be rendered at the head of each document stating: *"Notice: Lawyer review required prior to publication. Draft engineering scaffold."* To prevent unvetted placeholder pages from being indexed by search engines or discovered prematurely, the pages must be tagged with `noindex, nofollow` robots metadata, and footer links must remain off until placeholders are replaced. A separate audit check (`scripts/check-legal-placeholders.mjs`) is provided for release gating; routine production builds must NOT be blocked by placeholders.

## 2. Interface Contract
- **Routes:**
  - `GET /privacy`: Renders Privacy Policy scaffolding adhering to GDPR (Arts. 13/14) and CCPA/CPRA statutory structure.
  - `GET /terms`: Renders Terms of Service scaffolding establishing user covenants, acceptable use, and limitation of liability.
- **Top Notice Requirement:**
  Both pages must display a prominent alert banner at the top:
  `> **Notice:** Lawyer review required prior to publication. Draft engineering scaffold. Confirm wording and jurisdictional enforceability with a qualified attorney.`
- **SEO & Discovery Protection (Noindex & Footer Gate):**
  - **Noindex Metadata:** Both pages export Next.js metadata containing `robots: { index: false, follow: false }` so search engines never index placeholder copy.
  - **Footer Link Visibility:** Footer links to `/privacy` and `/terms` in `components/marketing/Footer.tsx` must remain disabled/hidden (or conditioned on an environment flag) until the owner provides real approved legal copy and replaces all placeholders.
- **Permitted Placeholders (strictly no invented text):**
  - `[OWNER: legal entity name]`
  - `[OWNER: postal address]`
  - `[OWNER: support email]`
  - `[OWNER: legal/privacy email]`
  - `[OWNER: governing law jurisdiction]`
  - `[OWNER: effective date]`
- **Dedicated Release Audit Script (Does NOT Block Routine Builds):**
  - Script: `scripts/check-legal-placeholders.mjs` (run manually or via `npm run check:legal`).
  - Scans `app/(marketing)/privacy/page.tsx`, `app/(marketing)/terms/page.tsx`, and `/dmca`.
  - Exits with code 1 and lists all unpopulated placeholders only when invoked as an explicit pre-launch release audit.
  - **Routine Deploy Policy:** Standard builds (`next build`) and routine CI runs must NOT be blocked by this script. It operates exclusively as a standalone pre-launch release gate.

## 3. Owner Role & Test Author
- **Owner Role:** Frontend Engineer
- **Test Author:** QA Engineer (QA writes route accessibility, content-assertion, noindex, and release-guard tests first)

## 4. Session Order (Multi-Phase Workflow)
1. **Phase 0 — Stubs (Frontend Engineer):** Create basic page route stubs at `app/(marketing)/privacy/page.tsx` and `app/(marketing)/terms/page.tsx`, and stub script `scripts/check-legal-placeholders.mjs`.
2. **Phase 1 — Tests First (QA Engineer):** Write `tests/marketing/legal-pages.test.ts` verifying:
   - `/privacy` returns 200 and renders the top "Lawyer review required" notice banner.
   - `/privacy` exports `robots: { index: false, follow: false }` metadata.
   - `/privacy` explicitly contains all required `[OWNER: ...]` placeholders and lists sub-processors (Supabase, Stripe, Google Gemini).
   - `/terms` returns 200, renders the top banner, exports `robots: { index: false, follow: false }` metadata, and contains required placeholders.
   - Footer links to `/privacy` and `/terms` remain disabled or gated off while placeholders exist.
   - **Standalone Release Guard:** Asserts that `node scripts/check-legal-placeholders.mjs` identifies remaining `[OWNER:` strings and exits with code 1 when audited, while standard build execution remains unblocked.
   - Confirm tests fail on assertions (red state).
3. **Phase 2 — Implementation (Frontend Engineer):** Implement pages, noindex metadata, footer gate, and audit script until tests pass (green state).
4. **Phase 3 — Independent Code Review (Code Reviewer):** Inspect diff to confirm zero invented legal text, verified noindex protection, and non-blocking build behavior.

## 10. Acceptance Criteria
1. **Static Rendering:** `/privacy` and `/terms` render cleanly with accessible HTML headings, readable typography, and responsive layouts.
2. **Mandatory Disclaimer:** Both pages display the conspicuous banner: *"Notice: Lawyer review required prior to publication. Draft engineering scaffold."*
3. **SEO Protection:** Both pages explicitly include `robots: { index: false, follow: false }` metadata.
4. **Gated Footer Links:** Footer links to `/privacy` and `/terms` remain disabled or hidden until placeholders are resolved.
5. **Structured Statutory Sections in `/privacy`:**
   - Identity & Contact Information (`[OWNER: legal entity name]`, `[OWNER: postal address]`, `[OWNER: legal/privacy email]`).
   - Categories of Data Processed (Account credentials, user-provided resume text, billing tokens).
   - Sub-Processors Named (Supabase for database/auth, Stripe for payment processing, Google Gemini for AI extraction).
   - User Rights (Access, Correction, Erasure via `/api/auth/account`, Data Portability).
6. **Structured Statutory Sections in `/terms`:**
   - Acceptance of Terms & Eligibility.
   - Ownership of Content (User retains full ownership of resume text).
   - Permitted Use & Restrictions (No automated scraping, no reverse engineering).
   - Paid Services & Pass Terms (One-time $19 30-day pass, no auto-renewal).
   - Limitation of Liability & Warranty Disclaimers (`[OWNER: governing law jurisdiction]`).
7. **No Invented Values:** All corporate data is represented via `[OWNER: ...]` placeholders.
8. **Non-Blocking Audit Script:** `scripts/check-legal-placeholders.mjs` runs on demand as a pre-launch release audit; standard `next build` continues to succeed cleanly during development.
