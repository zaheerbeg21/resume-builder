# T-015: Minimal LLM Provider Seam (Gemini adapter + fake provider)

## 1. Goal
A provider-neutral interface (LlmProvider), one Gemini adapter, and one offline fake provider. Explicit typed errors. Nothing else.

## 2. Deferred (out of scope, separate future ticket)
OpenAI-compatible adapter, failover router, circuit breaker, retries, caching, quota accounting, route integration. Do not implement or stub any of these.

## 3. Interface Contract (lib/ai/provider.ts)
export type ProviderName = 'gemini' | 'fake';
export interface GenerateParams<T> { systemPrompt: string; prompt: string; schema: z.ZodType<T>; abortSignal?: AbortSignal; }
export interface GenerateResult<T> { data: T; provider: ProviderName; model: string; latencyMs: number; inputTokens?: number; outputTokens?: number; }
export interface LlmProvider { readonly name: ProviderName; generateStructured<T>(params: GenerateParams<T>): Promise<GenerateResult<T>>; }
export type ProviderErrorKind = 'api' | 'timeout' | 'empty_response' | 'schema_validation';
export class ProviderError extends Error { kind, provider, status?, cause? }
systemPrompt is trusted application text; prompt is untrusted resume text. They are never concatenated.

## 4. Rules
- No silent fallback (rule 6): any failure throws ProviderError. Never return empty or fabricated data as success.
- Schema validation failure throws kind 'schema_validation'. The adapter never repairs output (rule 8).
- Gemini receives systemPrompt through the SDK's dedicated system-instruction field.
- Use the SDK's JSON response-schema mode if available, and still validate with Zod.
- No retries. One request timeout: REQUEST_TIMEOUT_MS in config, commented 'starting value, tuned on corpus'. Temperature 0 as TEMPERATURE constant.
- Never log prompt or resume text. Log only model, duration and error kind.
- API key from process.env.GEMINI_API_KEY, server-side only. Missing key throws at construction; it never falls back to the fake.
- Fake provider is injected explicitly in tests. It is never selected by an environment variable. It supports canned responses and a configurable failure.
- Model: lib/ai/config.ts exports DEFAULT_GEMINI_MODEL = 'gemini-3.5-flash-lite'; the adapter reads one optional override from GEMINI_MODEL_FAST. No model string anywhere else.

## 7. Phases

## 8. Acceptance Criteria
1. Gemini adapter and fake provider both implement LlmProvider.
2. A valid response returns data that passes the Zod schema, with provider, model and latencyMs set.
3. Each error kind is thrown for its case: API error, timeout (via abortSignal or REQUEST_TIMEOUT_MS), empty response, schema mismatch. Tests assert the exact kind.
4. A missing GEMINI_API_KEY throws on construction. It does not return the fake.
5. systemPrompt and prompt reach the SDK in separate fields (asserted with a mocked SDK).
6. No test performs a network call. Tests use the fake provider or a mocked SDK.
7. Model resolution: default is gemini-3.5-flash-lite; GEMINI_MODEL_FAST overrides it.
8. Nothing logs prompt text (test spies on console).

## 9. Stop Conditions
If the SDK cannot be mocked without live network calls in Vitest, stop and report.
