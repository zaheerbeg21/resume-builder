# T-015: AI Provider Seam, Failover Router & Circuit Breaker

## 1. Goal
Establish a resilient, provider-neutral AI layer that abstracts external LLM vendors behind a unified interface (`LlmProvider`). Implement adapters for Google Gemini (`@google/genai`) and OpenAI-compatible inference endpoints (`openai`), along with a zero-network fake provider for CI testing. Build a deterministic failover router and in-memory circuit breaker enforcing strict retry limits, non-failover error gates, and quota accounting rules.

## 2. Interface Contract
All AI route handlers and services must interact exclusively through the interface exported by `lib/ai/types.ts`:

```ts
import { z } from 'zod';

export type ProviderName = 'gemini' | 'openai-compatible' | 'fake';

export interface GenerateParams<T> {
  prompt: string;
  systemPrompt: string;
  schema: z.ZodType<T>;
  temperature?: number;          // Default 0 for extraction and parsing
  maxTokens?: number;
  abortSignal?: AbortSignal;
}

export interface TokenUsage {
  inputTokens: number;
  outputTokens: number;
  estCostUsd?: number;
}

export interface GenerateResult<T> {
  data: T;
  provider: ProviderName;
  model: string;                 // Configured identifier (TBD pending evaluation)
  failedOverFrom: ProviderName | null;
  latencyMs: number;
  usage: TokenUsage;
}

export interface LlmProvider {
  readonly name: ProviderName;
  generateStructured<T>(params: GenerateParams<T>): Promise<GenerateResult<T>>;
}

export type LlmErrorCode =
  | 'TIMEOUT'
  | 'NETWORK_ERROR'
  | 'RATE_LIMITED'      // HTTP 429
  | 'SERVER_ERROR'      // HTTP 5xx
  | 'VALIDATION_FAILED' // Zod parse failure or digit guard violation
  | 'AUTH_ERROR'        // HTTP 401/403 (Non-failover)
  | 'CONTENT_REFUSAL';  // Content moderation / policy refusal (Non-failover)

export class LlmError extends Error {
  constructor(
    message: string,
    public readonly code: LlmErrorCode,
    public readonly provider: ProviderName,
    public readonly status?: number,
    public readonly cause?: unknown
  ) {
    super(message);
    this.name = 'LlmError';
  }
}
```

- `lib/ai/router.ts`: exports `createAiRouter(config?: RouterConfig): LlmProvider` returning a router implementing `LlmProvider`.
- `lib/ai/circuit-breaker.ts`: exports `CircuitBreaker` tracking provider health.
- `lib/ai/adapters/gemini.ts`: exports `GeminiAdapter implements LlmProvider`.
- `lib/ai/adapters/openai.ts`: exports `OpenAiCompatibleAdapter implements LlmProvider`.
- `lib/ai/adapters/fake.ts`: exports `FakeLlmProvider implements LlmProvider` with fixture-based responses and deterministic failure simulation.

## 9. Failover & Resilience Specification

### 9.1 Failover Triggers (Fail Over to Fallback)
The router automatically intercepts and fails over to the secondary provider when the primary provider encounters:
1. **Timeout:** Request duration exceeds configured limit (e.g., 10,000ms).
2. **Network Error:** Connection drops, DNS lookup failure, or TCP socket resets.
3. **HTTP 429:** Rate limit reached or quota exhausted on the provider end.
4. **HTTP 5xx:** Server errors (500, 502, 503, 504) returned by the upstream provider.

### 9.2 Validation & Digit-Guard Retry Policy
- If the provider returns a response that fails Zod schema validation or fails the server-side digit/provenance guard, the router **retries once on the same provider** with structured validation feedback.
- If the retry also fails validation, or if the primary encounters an eligible transport failure (timeout, 429, 5xx), the router **fails over once** to the secondary provider.
- If the secondary provider fails validation on its first attempt, it may retry once on the secondary provider.
- **Strict Limit:** Maximum of **3 total attempts** across all providers per user request.
- **Quotas:** User quota is decremented strictly once per user request, regardless of whether internal retries or failovers occur.

### 9.3 Non-Failover Triggers (Immediate Fail-Fast)
The router must **NOT** fail over on:
1. **HTTP 401 / 403 (Auth Errors):** Indicates invalid API keys, bad credentials, or billing suspensions. Failing over masks configuration bugs and burns secondary quota.
2. **Content-Policy / Safety Refusals:** Refusals triggered by safety filters or policy blocks must terminate immediately with a user-friendly error. Failing over to another provider risks policy circumvention.

### 9.4 Circuit Breaker Specification
- **Threshold:** Trips open after **5 eligible failures within a 60-second sliding window**.
- **Open State Duration:** Remains Open for **5 minutes (300 seconds)**, during which all calls immediately bypass the primary provider and route directly to the fallback adapter (or fail fast if fallback is also tripped).
- **Half-Open Probe:** After 5 minutes, allows a single probe request through:
  - If the probe succeeds, circuit resets to **Closed**.
  - If the probe fails, circuit resets the 5-minute **Open** cooldown.

### 9.5 Quota Accounting Rule
- User quota must be counted **strictly per user request**.
- Internal retries and failover attempts are system resilience measures and must **never** decrement additional user quota.
- When an operation succeeds after failover, the `usage_events` record logs `failed_over_from` pointing to the primary provider, along with the actual executing provider, model, and aggregate latency.

## 10. Acceptance Criteria
1. **Contract Adherence:**
   - Both `GeminiAdapter`, `OpenAiCompatibleAdapter`, and `FakeLlmProvider` strictly implement `LlmProvider`.
   - All responses return typed data validated by the provided Zod schema.
2. **Deterministic CI Mocking:**
   - `FakeLlmProvider` runs entirely in-memory without network connectivity.
   - Vitest test suite executes completely with zero network requests.
3. **Failover Execution:**
   - On simulated timeout, network error, 429, or 500 from primary, the router transparently invokes the fallback provider and returns `failedOverFrom = 'gemini'`.
   - On Zod validation failure, the router retries once on primary; upon second validation failure, it attempts the fallback once.
   - Total attempts never exceed 2.
4. **Fast-Fail on Auth & Refusals:**
   - 401, 403, and content-policy errors throw `LlmError` immediately with `code: 'AUTH_ERROR'` or `code: 'CONTENT_REFUSAL'` without triggering failover.
5. **Circuit Breaker State Machine:**
   - 5 failures within 60s trips circuit breaker to `OPEN`.
   - Subsequent calls while `OPEN` bypass primary immediately without network delay.
   - After 300s, state transitions to `HALF_OPEN`. Successful probe transitions state to `CLOSED`.
6. **Telemetry & Latency:**
   - Result includes total cumulative `latencyMs` covering all execution attempts.
   - `failedOverFrom` is `null` when primary succeeds, or records primary provider name when fallback succeeds.

## 11. Open Risk / Infrastructure Note
- *Serverless State Limitation:* The breaker is best-effort only and may rarely trip on serverless. Real protection comes from short per-attempt timeouts and per-request failover; the breaker is an optimization. If timeout had no hits, also add this to the acceptance criteria: Per-attempt timeout is configurable per task via environment variables; worst-case latency (primary timeout plus fallback timeout) is documented and tested with the fake provider.
