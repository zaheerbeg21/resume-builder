# T-012: ATS Format Lint Engine

## 1. Goal
Implement a pure, deterministic ATS format linting engine that evaluates extracted PDF text and resume metadata to guarantee parsing health, verify standard heading sequences, detect unresolved AI placeholders, and ensure critical contact info is located in primary scan lines.

## 2. Owner Role & Test Author
- **Owner Role:** Document Engineer
- **Test Author:** QA Engineer (QA writes golden test fixtures and assertions *before* lint implementation)

## 3. Allowed Files
- `lib/pdf/lint.ts` (Core linting rules and evaluation engine)
- `lib/pdf/format-lint.ts` (Format score calculation contributing to the 10-point format match score)
- `tests/fixtures/resumes/lint-valid.json` (Passing fixture)
- `tests/fixtures/resumes/lint-invalid-headings.json` (Missing headings fixture)
- `tests/fixtures/resumes/lint-placeholders.json` (Unresolved `[...]` tokens fixture)
- `tests/fixtures/resumes/lint-missing-contact.json` (Contact info placed after line 15 fixture)

## 7. Acceptance Criteria
1. **Pure Function Interface:**
   - Implements `lintResume(extractedText: string, resume: Resume): LintResult`.
   - Never performs network I/O or database queries. Completely deterministic.
2. **Lint Checks Performed:**
   - **Contact Line Placement:** Verifies user's name and contact information appear in the first 15 lines of extracted text (ensures ATS header parsers capture identity).
   - **Standard Headings Order:** Verifies that recognized headings (`Summary`, `Experience`, `Projects`, `Education`, `Skills`) appear in order without non-standard terminology.
   - **Date Presence:** Verifies every experience and education record has an identifiable date or date range in the text stream.
   - **Zero Unicode Artifacts:** Verifies complete absence of replacement characters (`\uFFFD`) and unprintable control characters.
   - **Zero Unresolved Placeholders:** Flags any remaining bracketed AI tokens (e.g. `[X%]`, `[N users]`, `[$amount]`). Unresolved placeholders cause `passed = false` and block PDF export.
   - **Bullet Word Count:** Flags bullets with fewer than 12 words (too brief) or greater than 32 words (too verbose) as warnings.
3. **Format Score Calculation (`lib/pdf/format-lint.ts`):**
   - Computes a normalized 0 to 1 score (`formatScore01`) used by the Keyword Match Score engine (Blueprint §7).
4. **Result Schema:**
   - Returns:
     ```ts
     export interface LintResult {
       passed: boolean; // false if any hard errors exist (e.g., placeholders, garbled text)
       score: number; // 0 to 100
       formatScore01: number; // 0.0 to 1.0
       errors: string[]; // Block export
       warnings: string[]; // Informational
     }
     ```
5. **QA Test Suite (`tests/pdf-lint.test.ts`):**
   - Asserts valid resume fixture passes with 0 errors and `formatScore01 >= 0.95`.
   - Asserts presence of `[X%]` triggers hard failure.
   - Asserts contact info after line 15 triggers warning/error.
   - Asserts non-standard headings are flagged.
