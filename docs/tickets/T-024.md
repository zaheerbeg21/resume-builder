# T-024: LLM Semantic Resume Parser Adapter (Stage 1 Plain-Text)

## 1. Goal
Implement `lib/ai/parsers/resume-parser.ts` to convert extracted resume text into a structured `ResumeImportDraft` object. In Stage 1, ingest plain text via `pdf-parse` v2 accompanied by a generic layout-awareness directive instructing the model that multi-column blocks may appear detached. Route invocations strictly through the `LlmProvider` interface (T-015), enforce strict channel separation between system instructions and untrusted resume text, apply the n-gram containment provenance guard (T-023), and execute the 3-attempt resilience retry loop conforming to ADR-023.

## 7. Acceptance Criteria
1. **Interface Contract & Channel Separation:**
   - Interacts with LLM models exclusively via `LlmProvider.generateStructured<ResumeImportDraft>()`.
   - `systemPrompt`: Static instructions enforcing verbatim extraction, prohibiting fabrication, and commanding `null` on unstated facts.
   - `prompt`: Contains extracted resume text and generic layout instruction. No untrusted text is injected into the system prompt channel.
2. **Stage 1 Generic Layout Prompting:**
   - Prompt includes the standard directive: *"The source text is extracted from a PDF document that may contain multi-column sections, sidebars, or out-of-order text blocks. Use context, headings, and semantic associations to reconstruct the correct chronological experience, education, and skills."*
3. **Deterministic Grammars Integration:**
   - Pre-scans and normalizes email (RFC 5322), phone numbers (E.164), and URLs before or alongside LLM extraction.
4. **Retry & Failover Controller (ADR-023 Alignment):**
   - Configures per-attempt timeout at 8,000ms *(starting value, to be set from measured p95 latency in eval harness T-016)*.
   - On Zod schema or provenance guard failure: retries once on the same provider with feedback.
   - On transport failure (timeout, 429, 5xx): transparently fails over to secondary provider.
   - Enforces strict ceiling of **3 total attempts** across all providers.
5. **Provenance Guard Execution:**
   - Passes LLM output through `verifyProvenance()` (T-023) prior to returning; flags low-confidence paths and sanitizes ungrounded strings to `null`.
6. **Zero Network CI Mocking:**
   - Executes offline under Vitest using `FakeLlmProvider`.
