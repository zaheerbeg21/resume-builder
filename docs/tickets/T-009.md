# T-009: Guided Resume Editor — Part 1: State Store (Zustand & Autosave), Contact, Summary, & Skills

## 1. Goal
Implement the client-side Zustand resume state management store with debounced automatic backend persistence, and build the initial guided editor sections for Contact (Basics), Professional Summary, and Categorized Skills.

## 2. Owner Role & Test Author
- **Owner Role:** Frontend Engineer
- **Test Author:** Frontend Engineer

## 3. Allowed Files
- `lib/store/resume-store.ts` (Zustand store with optimistic updates and debounced sync)
- `app/(app)/resumes/[id]/edit/page.tsx` (Editor layout and hydration container)
- `components/editor/EditorHeader.tsx` (Title input, template switcher, autosave status indicator)
- `components/editor/BasicsSection.tsx` (Contact details and external portfolio/social links)
- `components/editor/SummarySection.tsx` (Executive summary textarea with character limiter)
- `components/editor/SkillsSection.tsx` (Categorized skill groups and tag manager)
- `tests/store/resume-store.test.ts` (Store action and autosave debounce unit tests)
- `tests/components/editor-part1.test.tsx` (Component interaction and form validation tests)

## 4. Human-Only Prerequisites
- Human approval for adding `zustand` to `package.json`.

## 5. New Dependencies for Human Approval
- `zustand` ^5.0.0 (client-side state management for fast, unbundled reactive updates).

## 6. Dependencies
- T-003 (Core Resume Schema)
- T-008 (Resume CRUD API)

## 7. Acceptance Criteria
1. **Zustand Resume Store (`lib/store/resume-store.ts`):**
   - Maintains active resume state adhering to `ResumeSchema`.
   - Exposes atomic update actions (`updateBasics`, `updateSummary`, `addSkillGroup`, `removeSkillGroup`, `addSkillItem`, `removeSkillItem`).
   - Tracks save status: `'idle' | 'saving' | 'saved' | 'error'`.
   - Debounced sync: automatically queues a `PUT /api/resumes/[id]` 1000ms after the user ceases typing.
   - Handles network failure gracefully: switches status to `'error'` and provides an explicit "Retry" action.
2. **Editor Header (`components/editor/EditorHeader.tsx`):**
   - Displays and allows editing the resume title.
   - Shows live autosave status ("Saving...", "All changes saved", or "Save error").
   - Template selector toggle between 'Standard' and 'Classic'.
3. **Contact / Basics Section (`components/editor/BasicsSection.tsx`):**
   - Form inputs for `fullName`, `headline`, `email`, `phone`, `location`.
   - Dynamic link list allowing up to 5 external links (e.g., LinkedIn, GitHub, Portfolio) with label and URL validation.
4. **Summary Section (`components/editor/SummarySection.tsx`):**
   - Textarea for professional summary with a live character count indicating remaining space up to the 600-character maximum.
5. **Skills Section (`components/editor/SkillsSection.tsx`):**
   - Allows users to create skill groups (e.g. "Languages", "Frameworks", "Cloud & Tools").
   - Allows adding and removing individual skill pills within each group.
6. **Persistence on Reload:**
   - Loading `/resumes/[id]/edit` fetches initial data from `/api/resumes/[id]` and hydrates the Zustand store without layout shifts. Edits survive browser page reload.
7. **Test Suite:**
   - `tests/store/resume-store.test.ts` validates state updates and verifies the 1000ms debounced save trigger.
   - `tests/components/editor-part1.test.tsx` verifies form rendering, user input updates, and character limit warnings.
