# T-020: Secure Upload: Signed-URL Private Storage Pipeline & `parse_jobs` Schema

**Status:** IMPLEMENTATION COMPLETE — ACCEPTED — RELEASE VERIFICATION PENDING

## 1. Goal
Implement a secure, tenant-isolated upload pipeline backed by private Supabase Storage (`resumes-raw`) to circumvent Vercel's serverless function request body limits (~4.5 MB; *verify in current Vercel docs*) and eliminate server memory buffering. Provide an authenticated upload-URL endpoint with per-user rate limiting, storage RLS policies, server pre-flight verification guards, and the `parse_jobs` table supporting asynchronous job polling as defined in ADR-022.

## 7. Acceptance Criteria
1. **Private Bucket Configuration:**
   - Bucket `resumes-raw` is private (`public = false`), enforces maximum file size of 5 MB (`5242880` bytes), and allows only `application/pdf`.
2. **Storage RLS:**
   - Authenticated users can generate signed URLs and write objects only under their own directory prefix `${auth.uid()}/${upload_id}.pdf`. Cross-tenant reading or writing is blocked.
3. **Signed URL Endpoint (`POST /api/resumes/upload-url`):**
   - Requires valid session auth.
   - Enforces PostgreSQL-backed rate limit (5 requests per user per 60 seconds) with saturation ceiling at 6.
   - Fails closed on database error/timeout with HTTP 503 (`Retry-After: 5`).
   - Returns short-lived signed upload URL (expiry starting value: 120 seconds) and canonical `storagePath` only upon successful admission.
4. **Pre-flight & Magic Byte Verification:**
   - Helper `verifyUploadedResume(storagePath, userId)` validates that the file exists, belongs to `userId`, size $\le 5\text{ MB}$, and reads the first 4 bytes to assert `%PDF`.
5. **`parse_jobs` Table Migration:**
   - Migration creates `parse_jobs` (`id uuid`, `user_id uuid`, `storage_path text`, `status text`, `result jsonb`, `error text`, `created_at`, `updated_at`, `expires_at`).
   - RLS policy `own_jobs` restricts select/insert/update to `auth.uid() = user_id`.
6. **Purge & Cleanup Helpers:**
   - `purgeUploadedResume(storagePath)` uses the service role to delete the raw object in a `finally` block.
   - Bounded single-worker collect-then-delete cleanup (`cleanupExpiredResumeUploads`) purges expired jobs and orphan files older than 1 hour, strictly capped at 500 objects per run.
