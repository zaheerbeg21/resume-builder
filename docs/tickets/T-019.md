# T-019: Spike: `pdfjs-dist` Direct Import & Serverless Runtime Compatibility (Conditional Stage 2)

## 1. Goal
Validate that `pdfjs-dist` (version 5.4.296, currently vendored via `pdf-parse`) can be imported directly and executed in Node.js serverless environments (Next.js App Router on Vercel) and Vitest test runners without triggering ambient DOM errors (`DOMMatrix is not defined`, `Path2D is not defined`, `canvas` missing). Establish the minimal polyfill and configuration required to extract structured `TextItem` coordinates cleanly.

*Staging Note:* This ticket is conditional (Stage 2). It will only be scheduled and implemented if Stage 1 plain-text extraction fails to achieve the starting multi-column accuracy thresholds ($\ge 85\%$ recall, $\ge 90\%$ precision) on the T-016 evaluation fixtures.

## 2. Owner Role and Test Author
- **Owner Role:** Document Engineer
- **Test Author:** QA Engineer (QA writes automated test harness asserting headless PDF loading without DOM errors)

## 3. Allowed Files
- `lib/pdf/pdfjs-spike.ts`
- `tests/pdfjs-runtime.test.ts`
- `package.json`
- `next.config.ts`

## 4. Human-Only Prerequisites
- Human approval to declare `pdfjs-dist` as an explicit direct dependency in `package.json`.
- Human confirmation that Stage 1 benchmark in T-016 missed starting accuracy thresholds, activating Stage 2.

## 5. New Dependencies for Human Approval
- `pdfjs-dist@5.4.296` (Direct dependency declaration in `package.json`). Direct inspection via `npm ls pdfjs-dist` confirms this package is already present in `node_modules` as a transitive dependency of `pdf-parse@2.4.5`.

## 6. Dependencies
- Prerequisites: Triggered only upon failure of Stage 1 benchmark in T-016.
- Feeds: T-022 (Layout-Aware Spatial Stream Extractor).

## 7. Acceptance Criteria
1. **Zero-DOM Headless Execution:**
   - Test harness initializes `pdfjs-dist` under Vitest and Node without throwing `DOMMatrix`, `Path2D`, or `window` errors.
2. **Coordinate Extraction:**
   - Successfully extracts `TextContent.items` from a sample PDF buffer and asserts that `transform` coordinates (`[scaleX, skewY, skewX, scaleY, x, y]`) and bounding dimensions (`width`, `height`) are non-empty numbers.
3. **Serverless Bundle Compatibility:**
   - Next.js build succeeds without worker-resolution syntax errors (`npm run build`).
4. **Stop Conditions:**
   - If `pdfjs-dist` requires native C++ binary bindings or `@napi-rs/canvas` to extract plain text items and geometry, **STOP and report immediately**. Plain text extraction must execute in pure JavaScript.
   - If importing `pdfjs-dist` in a serverless route requires modifying Vercel system libraries or global Node flags not supported in Next.js 16 App Router (*verify in current Vercel docs*), **STOP and report immediately**.
