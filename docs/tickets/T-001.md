# T-001: PDF Round-Trip Spike (React-PDF → pdf-parse v2)

## 1. Goal
Validate the core technical hypothesis that `@react-pdf/renderer` can render a structured resume JSON into a clean, single-column PDF in Node.js using embedded Inter static TTF fonts, and that `pdf-parse` v2 can extract the text with 100% fidelity (no garbled characters, preserved diacritics, intact ligatures, no hyphenation splits, and verified reading order).

## 2. Interface Contract
The spike establishes the baseline interfaces consumed by subsequent tickets:
- `types/resume.ts`: exports `ResumeSchema` (minimal Zod schema for spike) and inferred TypeScript type `Resume`.
- `lib/pdf/fonts.ts`: exports an idempotent function `registerFonts(): void` ensuring fonts are registered only once per runtime process.
- `lib/pdf/templates/standard.tsx`: exports `<ResumeDocument resume={resume} />` (accepting `{ resume: Resume }`) returning a `@react-pdf/renderer` `<Document>`.
- **Date Display Format:** Resume dates must be formatted and displayed as `Jun 2022 - Present` (or `Jun 2022 - Dec 2023` when `current` is false; month abbreviated as 3 letters `MMM YYYY`).

## 10. Acceptance Criteria
1. **Single-Column ATS Layout:**
   - Layout strictly single column: no multi-column grids, no tables, no graphic icons, no decorative images.
   - Page margins: strictly 0.65 in (46.8 pt).
   - Body font size: 10.5 pt, line-height 1.3 to 1.4.
2. **Idempotent Font Registration:**
   - `lib/pdf/fonts.ts` exports `registerFonts(): void`. Multiple invocations do not throw or re-register.
   - Registers `public/fonts/Inter-Regular.ttf` and `public/fonts/Inter-Bold.ttf` using absolute filesystem paths: `path.join(process.cwd(), 'public', 'fonts', 'Inter-Regular.ttf')`.
   - Browser URL registration logic (`/fonts/...`) is stubbed in code but explicitly **not verified** in this ticket (carried forward to T-013).
3. **Font Embedding Verification (No Fallbacks):**
   - Asserts that the rendered PDF buffer embeds the Inter font with a subset prefix (`/\+[A-Za-z0-9]*Inter/` or `/\+Inter/`).
   - Asserts that the raw PDF buffer does NOT reference `Helvetica` or `Times` as `/BaseFont`.
   - Confirm and document the exact font descriptor pattern on real generated output during the spike.
4. **Hyphenation Disabled (Test-Local Proof & Manual Red Demonstration):**
   - Hyphenation is disabled globally via `Font.registerHyphenationCallback((word) => [word])` in `lib/pdf/fonts.ts`.
   - Test design: uses a **test-local narrow-container component** (e.g. `<View style={{ width: 50 }}><Text>InternationalizationInfrastructure</Text></View>`) inside the test file, NOT inside `standard.tsx`.
   - Automated assertion: Asserts that unbroken over-wide words stay intact in extracted text without injected hyphens.
   - One-time manual demonstration: During the spike, Document Engineer temporarily removes the callback, runs the test, observes red output where React-PDF splits the word with a hyphen, restores the callback, and records this demonstration in the review notes.
5. **Text Normalization & Exact Ligature Matching:**
   - Extracted text from `pdf-parse` v2 and expected fixture text are compared after `.normalize('NFC')` and passed through a shared whitespace normalization helper (`text.replace(/\s+/g, ' ').trim()`).
   - Words containing common typographical ligatures (`Certified`, `workflow`, `office`) must be verified with exact string equality (`toBe('Certified')`, etc.), asserting that characters did not merge into single unparseable glyphs or drop letters.
6. **Accented Character Fidelity & Zero U+FFFD:**
   - All four fixtures (`spike-basic.json`, `spike-two-page.json`, `spike-accented.json`, `spike-polish.json`) extract with **zero replacement characters** (`!text.includes('\uFFFD')`).
   - Accented names (`Renée Noël Müller` and `Łukasz Żółć`) match 100% with exact string equality after NFC normalization.
7. **Dynamic Reading Order Verification:**
   - Fixture strings are unique across headings, titles, dates, and bullets.
   - The test dynamically queries indices for each element directly from the fixture data structure (not hardcoded literals):
     - Asserts every index is found (`index >= 0`).
     - Asserts indices strictly increase in document reading order: `nameIndex < headlineIndex < summaryIndex < exp1CompanyIndex < exp1DateIndex < exp1BulletIndex...`.
8. **Strict Page Count Assertions via `pdf-parse` v2:**
   - Checks page count using `(await parser.getText()).total` (or `result.pages.length` from `TextResult` in `pdf-parse` v2):
     - `spike-basic.json`: exactly 1 page.
     - `spike-accented.json`: exactly 1 page.
     - `spike-polish.json`: exactly 1 page.
     - `spike-two-page.json`: comfortably and exactly 2 pages.
9. **Class-Based `pdf-parse` v2 API:**
   - Strictly uses `const parser = new PDFParse({ data: buffer }); const result = await parser.getText(); await parser.destroy();`. Deprecated v1 functional calls (`pdf(buffer)`) are forbidden.
