# T-031: Remove page furniture before the model sees the text

## Goal
parseResume removes pdf-parse page markers and header or footer lines that repeat across pages, before the text reaches the model. Fixture 07 is the failing test.

## Rule basis
Rules file rule 4: library artifacts are removed by library structure or generic repetition detection, never by resume wording.
Rules file rule 9: fix failure classes across languages and layouts rather than individual fixtures (language-agnostic pagination normalization, keep-first retention for verbatim edge repeats, short-page body protection, and raw-source missing-contact warning parity).
Rules file rule 13: named edge window constant (`EDGE_LINE_WINDOW = 3`, `'starting value, tuned on corpus'`) clamped relative to page length so body lines on short pages are preserved.

## Behaviour (new helper lib/ai/helpers/page-furniture.ts: removePageFurniture(text) -> { text, removedCount })
1. Pages are split on the standalone pdf-parse marker line, matched by shape only: '-- N of M --' with integers. On multi-page documents (>= 2 non-empty pages), marker lines are removed and do not increment `removedCount`.
2. For each page take the first `W` and last `W` non-empty lines, where `W = Math.min(EDGE_LINE_WINDOW, Math.floor((nonEmpty.length - 1) / 2))` and `EDGE_LINE_WINDOW = 3` ('starting value, tuned on corpus'; blank lines do not consume slots). Pages with 5 non-empty lines therefore use `W = 2` and leave the middle body line untouched; pages with <= 2 non-empty lines use `W = 0`.
3. Normalise each edge line: trim, collapse whitespace, case-fold, and replace digits with '#' only inside explicit pagination expressions across languages — structural `<Word> <N> <connector> <M>` forms (`Page 1 of 2`, `Seite 1 von 2`, `Página 1 de 3`, etc.), explicit single-number prefixes (`Page N`, `pg. N`, `p. N`, `Seite N`, `Página N`), and CJK forms (`第Nページ` / `第N页` / `第N頁`) — recording `hasPagination`, while preserving unrelated numbers (`2021-03 - Present`, `Employment Period 2021`, phone numbers, metric figures, and bare `1/2` or `- 1 -`).
4. When a normalised complete line appears in the same edge (top or bottom) of at least 2 distinct pages: if `hasPagination` is true (or `isPaginated`), remove all copies across those pages and increment `removedCount`; if `hasPagination` is false (verbatim repeat such as Page 1's top name/contact line repeated on Page 2 or Page 3), keep the earliest page's copy and remove only duplicates on subsequent pages, incrementing `removedCount` for each removed duplicate. On remaining edge lines, strip whitespace-delimited inline `Page N of M` tokens whose normalised key appears in the same edge across at least 2 distinct pages while preserving surrounding contact details and without incrementing `removedCount`. Lines or tokens in body positions, seen only once, or appearing only across opposite edges are never removed.
5. A document with fewer than 2 pages is returned unchanged (`removedCount = 0`), and CRLF (`\r\n`) vs LF (`\n`) line endings are preserved.
6. The cleaned text is given to the model, the unslotted check, and guardProvenance (T-024 section 3 contract); missing-email and missing-phone warnings check raw `sourceText` so contact text on a removed header/footer still warns when extracted field is `null`.
7. If removedCount > 0 add the warning 'Removed N repeated page lines.' (complete-line count only, never text).

Artifact categories:
- PDF page marker lines: standalone `-- N of M --` integer lines emitted by `pdf-parse`; removed when >= 2 pages, not counted in `removedCount`.
- Repeated complete header/footer lines: whole non-empty lines inside top/bottom K edge slots whose pagination-normalised form repeats in the same edge across >= 2 pages; removed and counted in `removedCount`.
- Same-edge inline `Page N of M` tokens embedded in contact/header lines (for example Fixture 07 lines 1 and 16): only the whitespace-delimited `Page N of M` token is stripped when repeated in the same edge across >= 2 pages, keeping surrounding contact details intact and without incrementing `removedCount`.

## Fixtures
Fixture 07 and its twin lack pdf-parse markers. Real extraction emits them (see fixture 09), so add them to 07 and the twin. T-031 is restricted to Fixture 07 and its entity-swap twin; Fixtures 10 (Word PDF), 11 (LaTeX), and 12 (Canva) are reserved for Phase C.

## Acceptance criteria
1. Markers removed. 2. 07's repeated footer lines (digit-different) removed. 3. A line seen once is kept. 4. The same text at the top of one page and the bottom of another is kept. 5. One-page text is unchanged. 6. Exact warning text, count only. 7. Entity-swap invariance, plus one non-Latin line. 8. Input not mutated, nothing logged. 9. 07 and its twin show no surplus unslotted words.
