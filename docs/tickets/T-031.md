# T-031: Remove page furniture before the model sees the text

## Goal
parseResume removes pdf-parse page markers and header or footer lines that repeat across pages, before the text reaches the model. Fixture 07 is the failing test.

## Rule basis
Rules file rule 4: library artifacts are removed by library structure or generic repetition detection, never by resume wording.

## Behaviour (new helper lib/ai/helpers/page-furniture.ts: removePageFurniture(text) -> { text, removedCount })
1. Pages are split on the pdf-parse marker line, matched by shape only: '-- N of M --' with integers. Marker lines are removed.
2. For each page take the first K and last K non-empty lines (K is a named constant, 'starting value, tuned on corpus', start 3). Normalise each: trim, collapse whitespace, case-fold, replace digit runs with '#'.
3. A normalised line that appears in the same edge (top or bottom) of at least 2 pages is furniture. Remove those lines. Lines anywhere else, and lines seen once, are never removed.
4. A document with fewer than 2 pages is returned unchanged.
5. The cleaned text is the single string given to the model, the unslotted check and guardProvenance (T-024 section 3 contract).
6. If removedCount > 0 add the warning 'Removed N repeated page lines.' (count only, never text).

## Fixtures
Fixture 07 and its twin lack pdf-parse markers. Real extraction emits them (see fixture 09), so add them to 07 and the twin. Add fixture 10: a fabricated Word PDF with a real header and footer, extracted with the same call as the route.

## Acceptance criteria
1. Markers removed. 2. 07's repeated footer lines (digit-different) removed. 3. A line seen once is kept. 4. The same text at the top of one page and the bottom of another is kept. 5. One-page text is unchanged. 6. Exact warning text, count only. 7. Entity-swap invariance, plus one non-Latin line. 8. Input not mutated, nothing logged. 9. 07 and its twin show no surplus unslotted words.
