# T-023: Deterministic Provenance Guard: N-Gram Containment & Pairing Verifier

## 1. Goal
Implement a pure TypeScript verification module (`lib/ai/guards/provenance.ts`) that validates LLM-extracted resume data against the raw PDF source stream. Guarantee that every company, job title, school, degree, and date in `ResumeImportDraft` appears in the source text. Verify spatial pairing between companies, titles, and dates, and evaluate unstructured blocks (summary, bullets) using word n-gram containment against anchored source regions. Convert ungrounded strings to `null` and record warnings for unmapped source dates.

## Signature
   guardProvenance(draft: ResumeImportDraft, sourceText: string): { draft: ResumeImportDraft; report: ProvenanceReport }
   sourceText keeps its line breaks. ProvenanceReport is defined in types/provenance.ts: { nulledPaths: string[]; removedSkillPaths: string[]; unmappedDateRanges: string[]; decoupledRoles: string[] }. No new ReviewFlag reasons are added; lib/ai/schemas.ts is not edited.

## 7. Acceptance Criteria
1. **Contiguous Normalized Matching:**
   - Evaluates strings in `experience[].company`, `experience[].title`, `education[].school`, `education[].degree`, and `skills[].items`.
   - Normalizes both source stream and entities (case-folded, whitespace collapsed, punctuation stripped).
   - Any string that does not appear as a contiguous substring in normalized source text is replaced with `null` and its path is appended to `low_confidence_paths`.
2. **Word N-Gram Containment (Summary & Bullets):**
   - Evaluates summary and experience/project bullets using word n-gram containment:
     $$\text{Containment} = \frac{\left| \text{ngrams}(\text{output}) \cap \text{ngrams}(\text{source\_region}) \right|}{\left| \text{ngrams}(\text{output}) \right|}$$
   - Uses trigrams for standard text; uses bigrams for short fields ($\le 6$ words).
   - Enforces a starting containment threshold of $\ge 0.85$ *(starting value tuned on the corpus)*.
3. **Anchored Source Region Selection:**
   - The matching source region $\text{source\_region}$ is restricted to the text span anchored by the field's section heading or nearest verified neighboring entities (e.g. bounded between Role $i$'s title and Role $i+1$'s title), not the entire document.
4. **Invented Clause Rejection Assertion:**
   - Evaluates directional safety: testing whether source text is contained in the output is unsafe because a model could generate a real bullet and append an invented clause (e.g. *"saving $2M"*) while maintaining high source recall.
   - Test suite explicitly includes an adversarial case where an LLM returns a legitimate extracted bullet with an invented metric clause appended (e.g. *"Refactored microservices architecture, increasing throughput by 40% and saving $2M"* where only the refactoring was in the source). The test must assert that containment drops below 0.85 and the guard rejects the bullet.
5. **Date Token Membership Verification:**
   - Scans source text for all date patterns using a universal date regex and parses all discovered source date tokens into normalized ISO format (`YYYY` or `YYYY-MM`).
   - Asserts that every parsed `start` and `end` date in experience and education exists within the set of normalized source dates. Dates outside the set are set to `null` and flagged.
6. **Spatial Pairing Verification:**
   - Checks that for each role, the company name, title, and date interval appear within a localized spatial window ($K$ lines in the extracted text stream). Decoupled dates are flagged.
7. **Date-Interval Mapping Warning:**
   - Any source date range that cannot be mapped to an experience or education item produces a structured entry in `warnings[]`, never causing a fatal parsing crash.

## 7a. Contract Decisions (added after Phase 1 review)
1. Ungrounded fields: summary becomes '' (path in report.nulledPaths). basics.links[i].url and projects[i].name become null. company, title, school, degree, fullName, email, phone become null. Every nulled path appears once in report.nulledPaths and once in draft.low_confidence_paths, in draft order.
2. Bullets and skills items are removed, not nulled. The path uses the original index (e.g. experience[0].bullets[2], skills[0].items[1]). Removed bullet paths go in report.nulledPaths; removed skill paths go in report.removedSkillPaths.
3. Spatial window: measured in lines from the company line to the date line. The title line must also fall inside the same SPATIAL_WINDOW_LINES window. A role outside the window goes in report.decoupledRoles as 'experience[i]'. The date is still kept.
4. Date matching: a draft year-only date ('2020') matches any source date in that year. Draft dates are normalized to YYYY or YYYY-MM. Supported formats in this version: MM/YYYY, YYYY-MM, YYYY, and English month names. 'Present' (English) maps to end: null and current: true. Other languages (including 現在) are out of scope; such dates are nulled and flagged.
5. Known limit: a long bullet with a short non-numeric invented tail can pass the 0.85 threshold. Accepted for the first version; measured on the corpus before any new rule is added.
6. Containment is checked together with the number/currency token check. A bullet is rejected if either fails.
7. Draft 'Present' is grounded only if the source contains an English 'Present' (case-insensitive) on the role's date line. Otherwise end is set to null, the path experience[i].end goes in report.nulledPaths, and current is left as the draft gave it.
