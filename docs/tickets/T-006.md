# T-006: Supabase Auth Session Handling, Server Client & Route Protection (proxy.ts)

## 1. Goal
Implement server-side Supabase client utilities with cookie-based session persistence, an OAuth/email exchange callback route, and server-side route protection using the official Next.js 16 `proxy.ts` convention (migrated from deprecated `middleware.ts`).

## 2. Owner Role & Test Author
- **Owner Role:** Backend Engineer
- **Test Author:** Backend Engineer

## 3. Allowed Files
- `proxy.ts` (Next.js 16 proxy file convention at project root)
- `lib/db/supabase-server.ts` (Server Component and Route Handler client factory)
- `lib/db/supabase-client.ts` (Browser Client Component client factory)
- `app/(auth)/callback/route.ts` (Auth callback route handler)
- `tests/auth/proxy.test.ts` (unit tests validating proxy routing and redirect logic)

## 4. Human-Only Prerequisites
- Human approval for adding the `@supabase/ssr` package to `package.json`.

## 5. New Dependencies for Human Approval
- `@supabase/ssr` (required for official Next.js App Router cookie-based session handling).

## 6. Dependencies
- T-002 (Local dev environment & secrets)
- T-004 (Core database tables and profiles)

## 7. Acceptance Criteria
1. **Next.js 16 Proxy Convention (`proxy.ts`):**
   - Implements `proxy.ts` in the project root exporting a named `proxy` function and config:
     ```ts
     import { NextResponse } from 'next/server';
     import type { NextRequest } from 'next/server';

     export async function proxy(request: NextRequest) {
       // Inspect session via Supabase server client
     }

     export const config = {
       matcher: ['/dashboard/:path*', '/resumes/:path*', '/billing/:path*', '/login', '/register'],
     };
     ```
   - Complies strictly with Next.js 16 documentation in `node_modules/next/dist/docs/01-app/03-api-reference/03-file-conventions/proxy.md`.
2. **Route Protection Logic:**
   - Unauthenticated requests accessing protected paths (`/dashboard`, `/resumes/*`, `/billing`) are redirected to `/login?returnTo=<encodedPath>`.
   - Authenticated requests attempting to visit `/login` or `/register` are redirected to `/dashboard`.
3. **Session Cookie Management:**
   - `lib/db/supabase-server.ts` uses `@supabase/ssr` with `cookies()` from `next/headers` to read and write auth cookies safely on Server Components and Route Handlers.
   - `lib/db/supabase-client.ts` initializes singleton browser client using `createBrowserClient`.
4. **Auth Callback Route (`app/(auth)/callback/route.ts`):**
   - Handles OAuth and magic link redirects with a `code` query parameter.
   - Exchanges `code` for an active user session via `supabase.auth.exchangeCodeForSession(code)`.
   - Redirects to `returnTo` or defaults to `/dashboard`.
5. **Proxy Unit Tests (`tests/auth/proxy.test.ts`):**
   - Asserts unauthenticated requests to `/dashboard` return 307 redirect to `/login`.
   - Asserts authenticated requests pass through to `/dashboard`.
   - Asserts authenticated requests to `/login` redirect to `/dashboard`.
