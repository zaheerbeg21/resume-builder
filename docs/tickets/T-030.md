# T-030: GDPR Compliance: Font Self-Hosting Assertion & Test Suite

## 1. Goal
Implement an automated compliance test suite (`tests/compliance/fonts.test.ts`) verifying that the application does not load or reference external third-party font servers (including `fonts.googleapis.com`, `fonts.gstatic.com`, or other remote CDN font providers) at runtime. The ticket explicitly delineates two distinct testing modes:
1. **Source-Only Inspection (executes under standard `npm test`):** Statically scans application source files (`app/layout.tsx`, `app/globals.css`, `next.config.ts`, `lib/pdf/fonts.ts`, and `components/`) to assert zero third-party font hostnames or remote `@import` rules in code.
2. **Production Build-Output Scanning (requires an explicit build step):** Inspects the `.next` production distribution bundle to assert zero external font host references in compiled HTML and CSS assets. This test is explicitly gated behind a prior `npm run build` step and is NOT claimed under plain `npm test`.

## 2. Interface Contract
- **Test File:** `tests/compliance/fonts.test.ts`
  - Automated Vitest test suite.
  - **Mode 1: Static Source Inspection (Default in `npm test`):**
    - Scans `app/layout.tsx`, `app/globals.css`, `next.config.ts`, and `lib/pdf/fonts.ts`.
    - Asserts zero string occurrences of `fonts.googleapis.com` or `fonts.gstatic.com`.
    - Asserts all React-PDF font references in `lib/pdf/fonts.ts` resolve to local filesystem paths (`process.cwd()/public/fonts/...`) or same-origin paths (`/fonts/...`).
    - Runs in < 200ms without network or build requirements.
  - **Mode 2: Production Build-Output Inspection (Requires Build):**
    - Checks whether `.next` production output exists (skips gracefully in plain unit test runs if unbuilt).
    - When `.next` exists (or when run via the dedicated build-verification command), scans generated static HTML, server bundles, and CSS files to confirm that Next.js did not emit external font stylesheet links.
    - Asserts that rendered React-PDF document buffers embed font data directly and contain zero references to external font URIs.
- **Exact Execution Commands:**
  - Fast source-only compliance scan: `npx vitest run tests/compliance/fonts.test.ts`
  - Full end-to-end build-output scan (PowerShell): `npm run build; npx vitest run tests/compliance/fonts.test.ts`

## 10. Acceptance Criteria
1. **Source-Only Scan Under `npm test`:** Plain `npm test` runs the static source inspection suite and passes without requiring a prior production build.
2. **Zero External Font URLs in Code:** Tests assert that neither `app/layout.tsx`, `app/globals.css`, nor any component under `components/` contains string references to `fonts.googleapis.com` or `fonts.gstatic.com`.
3. **Self-Hosted React-PDF Verification:** Asserts that all font files registered in `lib/pdf/fonts.ts` exist as physical `.ttf` files in `public/fonts/` (`Inter-Regular.ttf`, `Inter-Bold.ttf`, `SourceSerif4-Regular.ttf`, `SourceSerif4-Bold.ttf`).
4. **Explicit Build-Output Command:** The ticket documents the exact multi-step command (`npm run build; npx vitest run tests/compliance/fonts.test.ts`) required to verify production `.next` output.
5. **No Dynamic Remote Font Fetching:** Asserts that `Font.register` calls in `lib/pdf/fonts.ts` never pass an external HTTP/HTTPS URL outside of the local origin.

## 11. Open Risk / Infrastructure Note
- In local development mode (`next dev`), Next.js may fetch font files from Google once during initial build and caches them in `.next/cache`. In production deployment (`next build`), font files are fully baked into the static bundle.
