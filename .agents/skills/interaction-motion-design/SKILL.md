# Interaction and Motion Design

Use this skill for buttons, navigation, transitions, gestures, feedback, loading, and animated components.

## Define states
For each interactive component, specify default, hover (where relevant), focus, pressed, selected, disabled, loading, success, and error states.

## Motion principles
- Use motion to communicate cause/effect, continuity, hierarchy, or state change.
- Keep transitions brief and consistent with platform conventions.
- Avoid motion that delays task completion or blocks input.
- Respect reduced-motion preferences and provide non-animated alternatives.
- Ensure loading indicators communicate progress honestly.
- Use haptics only when they add meaningful confirmation and are platform-appropriate.

## Validate
Test interruption, repeated taps, slow network, reduced motion, keyboard navigation, and state restoration.

## Guardrails
Do not animate every element. Never use motion to conceal latency, mislead users, or make essential information difficult to access.
